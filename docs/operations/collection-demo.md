# 正常模式与快速采集演示入口

[文档导航](../README.md) · [正常采集流程](../features/screening.md)

两个入口使用同一份代码，分别运行。快速演示不会切换正常模式的 active_runtime，也不删除正常对话、待采集任务或已确认条目。

## 明确入口

| 模式 | 双击入口 | 网页入口与范围 |
|---|---|---|
| 正常模式 | [Open-NormalMode.cmd](../../Open-NormalMode.cmd) | 打开当前正常服务的 `/robot-care/voice`；具体端口以窗口显示为准。完整 PHQ-9／GAD-7 和六类指标，通话后复核、跨会话继续 |
| 快速采集演示 | [Open-CollectionDemo.cmd](../../Open-CollectionDemo.cmd) | 默认 `http://127.0.0.1:3091/login`；登录后进入语音陪伴。单轮近况触发，采集3项自定义指标并按实际回答计分 |
| 停止快速演示 | [Stop-CollectionDemo.cmd](../../Stop-CollectionDemo.cmd) | 仅停止快速演示的受控进程；正常服务继续运行 |

若默认端口被占用，启动器会选择可用端口并保存；后续继续使用该地址，始终以启动窗口显示为准。启动窗口会保留，并显示该入口对应的本机账号。两个模式的密码和数据独立，不要公开运行目录内的凭证。

正常数据继续由 `runtime/active_runtime.txt` 指向；快速演示固定使用 `runtime/collection_demo/demo.db`。前端分别构建在 `.next` 与 `.next-collection-demo`，首次演示需要单独构建，不覆盖正常网页。更新代码后需重启对应模式；仅打开健康的入口不会中断正在运行的服务。

语音仍需本机 `backend/.env` 中配置可用的豆包语音服务，密钥留在服务端，不复制到演示数据或提交 Git。项目依赖按[快速开始](../getting-started.md)安装。

## 一段短演示的操作顺序

以下是虚构演示台词，分数由本轮实际回答和核对计算。

1. 双击快速演示入口，使用窗口显示的演示账号登录。登录页和工作台均应显示“快速采集演示”。
2. 进入“语音陪伴”，点击“准备新一轮演示”，再点击“开始语音对话”。旧演示记录会保留。
3. 说：“最近心情有点低落，做事情没什么兴致，不过现在可以慢慢聊。”一句有依据的本人近况即可进入演示检测，不要求长篇倾诉。
4. 助手会逐项了解近两周的情绪与兴趣、精力与行动、自我评价与希望感。依次回答“有时”“经常这样”“较少”。针对明确的近两周条目问题，频率回答直接入账，不再要求逐项回答“对”；含糊或缺少时间范围时才补问。
5. 三项均确认后，语音页显示“已确认 3/3 项，演示指标合计 6/12”。更换频率答案会改变计分；缺少有效回答的条目不会补分。
6. 点击“结束并保存”，等待保存确认，再点“查看演示采集与分数”。量表页可看到来源完整的自定义指标合计及“快速演示”标识，也可生成本次报告。

自动触发暂未完成时，可在说过一句话、出现最终字幕后点击“手动启动演示（留痕）”。此操作只启动采集，不填写答案；结果会显示“人工触发演示”。

演示指标为3项、每项0—4分，合计0—12分。它不是缩短后的 PHQ-9／GAD-7，不输出临床分级；正常模式的题目数量、确认要求和合计规则保留。拒绝或危险表达仍会优先暂停采集，因此演示台词使用普通近况，不以危机表达强行启动问答。

## 隔离与验证

快速门槛须同时满足独立启动器设置的演示角色、非生产环境和演示数据库声明；正常环境不能用客户端参数开启。正常模式不会提供演示的手动启动和任务重置接口。

代码回归覆盖隔离保护、单轮证据、真实确认计分、来源更正后失效、拒绝及危险优先。浏览器协议联调用虚构语音模型事件经过实际 WebSocket、HTTP、保存和页面显示，验证了6/12合计；它属于软件联调。真实豆包的单轮检测另用虚构输入核查，普通闲聊未触发、本人低落近况触发3项演示。真人麦克风、听感及现场网络仍须会前走一遍。


## 自动推进与保存后核对

采集任务、已完成方向和下一项会持续带入语音提示。明确的口语频率（例如“偶尔”“常常”）可直接入账；单独的“是的”只有在问题已给出唯一明确频率时才采用。已完成方向的重复回答不会误记为另一项，未完成条目可以按实际提问顺序记录。含糊答案会触发温和澄清，正向经历不会被当作困扰计分。

每次通话会登记持久核对任务，并与采集任务在同一事务中保存。独立后台进程在通话结束、原话保存完整且没有同账号新通话进行时，自动复核遗漏的明确问答；写入答案、来源引用、进度和结果使用同一事务。任务可重复执行，也可在服务重启或文字重传完成后继续，不依赖开发人员运行补录脚本。原话改动会要求重新核实，跨用户、不同采集周期及已暂停或拒绝的任务不会强行合并。正常模式保持完整量表的确认和计分要求。

结果页显示“保存后自动核对”状态，并每隔约5秒自动更新。信息缺少时保留待采集任务，继续了解未完成方向；采齐才结束任务并生成合计。通话显示“保存成功”时，原会话占用也已释放，可立即开始下一次通话。

自动恢复验证使用虚构语音协议事件：刻意在采集指令下发之前完成三项回答，实时进度为0/3；保存后由独立后台进程自动核对为3/3、6/12，再核实网页显示。运行 `SHORT_DEMO_SCENARIO=late` 的 `backend/tools/check_short_demo.py` 可复查该场景；该测试属于模拟语音事件的软件联调。
