# 使用已有服务器权限取齐运行资料

接手人已有负责人提供的服务器账号和密码，无需再向负责人逐项索要应用密钥、数据库文件或私有安装包。公开源码和模型在 GitHub；真实运行材料集中保存在服务器私有交接目录，通过现有 SSH 权限下载。

## 下载

在新克隆的项目中使用 Python 运行：

```bash
python tools/fetch_private_handoff.py --host YOUR_SERVER_HOST --user YOUR_SSH_USER
```

服务器主机和账号使用负责人已经私下提供的值。脚本调用系统 OpenSSH scp，在其标准密码提示中输入已有服务器密码；不要将密码写入命令行或发到 GitHub。系统需安装 OpenSSH Client。

默认下载到被 Git 忽略的 `runtime/private-import`，并限制本地目录权限。脚本使用 `deploy/server-host-key.pub` 中的服务器公开主机密钥进行固定校验，服务器身份不匹配时拒绝连接，不关闭 SSH 校验。

下载后核对大小和 SHA-256，得到 `runtime-private.tar.gz`。已有目标文件时拒绝覆盖，可以用 `--output-dir runtime/private-import-new` 下载到新目录。不会自动解压或覆盖现有运行配置。

## 私有包中的资料

- 终端后台环境配置与豆包参数。
- 数据库与应用运行配置、受限设备连接密钥、管理员访问连接材料。
- 管理员应用凭据文件。
- 已生成的树莓派私有终端包和 Windows 管理员访问包。
- 打包时的服务器 PostgreSQL 快照、此前的本地和服务器 SQLite 备份。
- 中央服务环境与 systemd 配置。

私有包不内置下载时使用的运维 SSH 登录账号密码，也不包含 GitHub 登录凭据；受限设备的连接身份则属于包内运行配置。运维 SSH 信息沿用负责人已私发给接手人的资料。模型权重从公开的[模型交接附件](model-release.md)获取，不在这个私有包中重复存储。

## 恢复与开发

1. 在受保护的空目录检查归档清单，勿把解压内容明文提交到公开仓库。
2. 按当前开发电脑或树莓派修正绝对路径和运行环境。Windows 虚拟环境不适用于 ARM；权重资源也不代替 CPU/ARM 适配。
3. 正式业务数据继续留在服务器，不把备份恢复到终端作为离线生产库。
4. 私有终端包可按统一手册安装；需要更新应用时使用最新 main 源码和授权配置。

本次是交接时生成的一致性快照，并非持续同步。开发期间如需最新业务数据，接手人已有运维权限，可在服务器重新备份并核验；不要覆盖运行中的数据库。
