# 项目交接、后续任务与使用手册

整理日期：2026-11-22。本文面向下一位开发者，汇总当前实现、操作方法、验证边界与待办。当前架构以本文及 `docs/operations/edge-central.md` 为准；历史文档中的“全部运行在树莓派”或“SEGA 在服务器推理”等描述不代表当前交付。

源码仓库：<https://github.com/oGasshow/psychological-care-robot>。上传前远端基线为 `82169d7d3f40c095909cc075601c8267d376f258`；本次最终版本号以包含本文的 Git 提交为准。

## 1. 当前需求和部署分工

用户在树莓派本地登录、语音聊天、完成或续答量表；正式业务数据统一存放服务器；甲方在服务器管理员端查看各用户报告。

| 组件 | 运行位置 | 当前职责 |
|---|---|---|
| Next.js 用户网页 | 树莓派／本机终端 | 本地浏览器页面、登录操作、语音和量表界面 |
| FastAPI 用户 API | 树莓派／本机终端 | 用户认证、豆包语音桥接、量表采集、业务逻辑 |
| 分析 worker | 树莓派／本机终端 | 情绪任务、通话后复核、SEGA 任务、状态更新 |
| PostgreSQL | 服务器 | 用户及管理员账号、对话、答案、进度、分数、标记、报告与任务数据 |
| 只读管理 API 与网页 | 服务器 | 管理员登录、用户搜索、报告列表、查看和打印 |
| 豆包 | 外部服务 | 实时语音与相关模型服务；终端配置密钥 |

用户本地页面为 `http://127.0.0.1:3000/login`，不要求本地 HTTPS。终端到服务器数据库使用受限 SSH 加密隧道，数据库不开放公网端口。当前管理员也通过独立加密转发访问服务器网页；公网 HTTPS 域名、小程序、原生 App 尚未交付。

**数据与网页分工已实现，不等于树莓派整机和 SEGA ARM 推理已验收。**

## 2. 已完成的工作

### 2.1 用户、对话和量表

- 注册与登录；账号间记录隔离。后端按登录身份校验归属，修改会话编号不能读取他人记录。
- 同一账号可有多段独立会话。个人空间采用独立卡片，可查看详情、摘要及删除已结束的对话。
- 同账号的量表任务、已确认答案和陪伴状态跨会话保存。对话结束不等于取消未完成的量表。
- 用户明确暂停或拒绝时尊重其意愿；已完成内容保留。完成本轮量表后回到自然陪伴，不在下一次聊天中机械重做。
- 量表提问改为简短支持、一次一项、鼓励如实表达；保留题意、近两周范围和原有计分方向，不暗示选择低分答案。
- 四种音色：亲切女声、天才童声、小何、温柔妈妈；语速范围 0.5–2 倍，在新通话开始时应用。
- 已移除网页上的临时实验录音勾选内容及正常模式说明框等此前指定内容。

当前用户状态为“常规陪伴／待进一步了解／筛查高关注”。量表进度与关怀状态分开管理；完整、有效的 PHQ-9 默认以 10 分作为高关注阈值，复评间隔默认 14 天，均有配置。这里的状态属于软件辅助筛查，不是“确认患有抑郁症”。

覆盖率表示已确认条目数／总条目数；不完整量表展示已答小计、覆盖率或可能范围，不能把覆盖率称为经临床验证的可信度。

### 2.2 管理员端

- 专门授权的管理员账号，普通注册不产生管理权限；可撤销授权。
- 管理员只查找用户、选择历史报告、查看和打印／保存 PDF。
- 已移除管理员个人空间、聊天、量表填写、关怀跟进编辑和独立状态面板；管理 API 也移除了对应写接口。
- 管理端只列出已结束且记录收齐的会话；业务报告与测试报告分开查看。
- 普通用户不能进入管理员端；终端拒绝管理员登录，中央服务拒绝普通用户登录和普通业务处理。
- 用户端与管理端读取同一来源版本的报告；更正或删除原话会使旧报告文字失效。

### 2.3 数据与运行角色

- 支持 `standalone`、`edge`、`central` 三种角色。单机 SQLite 保留兼容；分布式角色强制 PostgreSQL，不回退写本地 SQLite。
- 当前开发电脑已切换为 edge：网页、API、worker 在本机，新业务数据写服务器。
- 本机数据库隧道已补充后台监督和断线重连；认证接口遇到存储故障返回明确提示。注册与登录已用真实服务器及终端数据库权限验证，测试账号通过事务回滚清理。
- 新终端语音记录不创建本地业务 SQLite 队列，暂未确认的文字只在 RAM 中保留，并可在进程仍存活时重试。
- 服务器使用独立只读管理数据库账号，只额外允许写访问审计；终端账号不能授予管理员权限或改写已有用户密码。
- 中央服务与终端的 JWT 签名密钥分开；设备不携带服务器 root 密码。
- SEGA 敏感特征临时目录在 edge 模式限定为 `/dev/shm` tmpfs；不支持该工作区时不启用自动提取。
- 已提供受限隧道启动工具、树莓派安装脚本、systemd 模板和 Windows 管理员访问启动器。

## 4. SEGA 的真实状态与优先待办

电脑此前使用作者中文 EATD `sega_best.pt`，没有为本平台重新训练。参考仓库 <https://github.com/zhchen18/SEGA>；参考提交 `0514201653d71728015cf4aea2816c9151b94f71`，权重 SHA-256：`f9b427f3928a56fde91e25265eea5aac8677e5fd4c369f2cb2ebac438cfbc8bd`。

1. **CPU／ARM 适配尚未完成。** 作者实现有硬编码 `.cuda()`；`backend/tools/sega_infer.py` 当前也会在没有 CUDA 时抛出 `author_reference_requires_cuda`。普通树莓派不能仅复制权重就运行。先保持权重不变，做设备适配并对照参考输出，再测内存和耗时。
2. **输入一致性尚未完全核验。** 模型需要题目和回答的文本特征、对齐音频 88 维特征、7 类情绪概率及有依据的性别编码。不是把一段转写文本直接输入分类器。不能以零向量或猜测值补齐模态。
3. **作者定制工具仍有缺口。** 已研究和部署过公开特征工具及项目提取器，但不能将公开工具等同作者当年的定制配置；需取得或核对完整编码器、窗口、步长等配置。
4. **日常对话误判尚未被证明解决。** 作者已有特征上能运行检查点，不代表本平台日常聊天达到论文指标。此前正常对话出现过原始 class=1；保留原始输出，并通过当前、同用户的来源依据约束自动任务，不能把业务护栏描述为模型已训练修复。
5. 当前网页已移除临时实验录音勾选，也不再发送该录音分析字段；后端／终端特征接口仍保留。不能声称每次网页聊天已经完整执行了真实 SEGA。现有对话上下文辅助采集与真正 SEGA 推理必须区分。

作者权重可继续作为基线；CPU 适配本身通常不要求重训。是否微调应在完成特征口径和独立业务验证之后决定。通用树莓派包不包含作者权重、Windows 虚拟环境或完整 ARM 推理环境。

## 6. 使用手册

### 6.1 普通用户

1. 在树莓派本地浏览器打开登录页，注册或登录自己的账号。
2. 选择音色及语速，允许麦克风后开始新对话；音色和语速在新通话开始时应用。
3. 平台根据对话线索在合适时了解量表方向，或在结束后复核并保留后续任务。无需用户记住特殊启动口令。
4. 未完成量表可在同账号后续对话继续；已完成本轮量表后继续自然交流。
5. 在个人空间查看对话、量表结果和报告；结束的对话可按确认流程删除。共享设备使用完后退出账号。

新终端模式需要服务器网络连接。保存未确认时不能解释为已保存；进程退出或设备断电会失去尚未确认的 RAM 数据。已提交的数据存于服务器，不承诺设备离线仍可完整持久采集。

### 6.2 管理员

在当前开发电脑运行 `Open-ServerReports.cmd`，或在其他 Windows 电脑使用负责人私下提供的管理员访问包，解压后运行 `Open-Reports.cmd`。需要 Windows OpenSSH Client；启动器优先打开 Chrome。

使用专门授权的管理员账号登录，搜索用户，选择历史报告。可刷新并打印／保存 PDF。默认查看业务记录；旧演示数据在测试范围。管理员没有普通用户功能，也不能在该端填写量表、编辑跟进或删除报告。

当前没有可在微信搜索的小程序，也没有已配置的公网网页域名。手机直接远程访问需补 HTTPS 域名与代理；小程序需另开发客户端、配置相应平台参数并接管理 API。

### 6.3 树莓派首次安装

使用负责人发放的**私有终端包**，不要把 Windows `.venv` 或 `node_modules` 复制到 ARM。解压后运行：

```bash
sudo bash deploy/edge/install-edge.sh
```

要求 64 位 ARM Raspberry Pi OS。脚本安装 Python 3.13、依赖和 Node，构建网页并安装四个 systemd 服务：`robot-care-edge-tunnel`、`robot-care-edge-api`、`robot-care-edge-worker`、`robot-care-edge-web`。

私有文件需包含 `edge.env`、`connection.env`、`edge_ed25519`、`known_hosts`。`connection.env` 指定服务器主机和受限设备账号；环境文件中指定 edge 角色、PostgreSQL 地址、应用签名密钥和豆包参数。公开模板在 `deploy/edge`。

安装后打开本机 `http://127.0.0.1:3000/login`，实际检查收音、播放、插话、结束、分段续答和保存。开机全屏浏览器自启动尚需按目标桌面环境配置。SEGA 权重与 ARM 环境另行配置和验收。

私有安装包包含连接凭据，不上传公开仓库。给不同设备发放独立设备密钥。Windows 管理访问包仅含报告转发凭据，不应含终端数据库密码或豆包密钥。

在获得负责人授权的私有配置后，可用 `tools/package_edge.py --private-dir <私有目录> --output-dir runtime/bundles` 重建两个安装包。私有目录需有前述四个终端文件，以及 `reports_ed25519`、`reports-connection.json`；后者仅指定管理员连接的服务器 `host`。脚本导出锁定依赖，排除数据库、模型权重和构建缓存，生成私有 ZIP 及校验清单。公开配置模板为 `deploy/edge/edge.env.example`、`connection.env.example`、`deploy/central.env.example` 和 `deploy/reports-windows/connection.json.example`。

## 7. 下一位开发者的任务顺序

### P0：交付完整树莓派链路

- 收集目标树莓派型号、内存、系统架构、音频设备与网络条件，安装并核验四个服务。
- 完成 SEGA CPU／ARM 设备适配、权重加载及对照输出检查，核验完整输入提取口径；测量速度和内存。
- 在独立测试账号上验证：正常聊天、出现需进一步了解的线索、量表分两次完成、下一段恢复自然陪伴、管理员查看相应报告。
- 检查网络中断、进程重启、设备断电、保存确认与重试提示，明确“未确认数据仅在 RAM”的产品边界。
- 验证同账号换设备续答、多用户和多设备并发；当前活跃通话的一些保护含进程内状态，跨设备并发不能仅凭单进程测试认定完成。

### P1：上线与运维

- 配置管理员公网 HTTPS 域名和反向代理；用户本地 HTTP 入口保持本机使用。
- 为每台终端管理私有配置和密钥发放、撤销；现有管理员授权通过本地运维命令完成。
- 补充持续备份、恢复演练、容量和访问日志管理；当前只证明初始备份存在，不声称已有完整自动备份策略。
- 针对真实用户、语言习惯和录音条件评估误判；区分论文指标、软件流程测试和实际业务效果。
- 优化高延迟网络下大量数据库往返；明确受信任终端的边界。若需要把设备当作不可信客户端，应另设计按用户鉴权的数据 API 或数据库行级权限，而非向普通客户端发数据库凭据。

### P2：后续产品

- 微信小程序／原生 App、微信登录及通知推送。
- 批量设备安装、版本升级与完整的设备管理。
- 依据评估结果再决定数据集、标注、微调或训练方案。

管理端使用 `POST /api/auth/login`、`GET /api/auth/me` 和四类只读接口：`GET /api/care-management/users`、`/users/{uid}`、`/users/{uid}/sessions`、`/reports/{sid}`。分页参数为 `q`（用户列表）、`is_test`、`limit`、`cursor`，游标绑定账号及查询范围。详细契约见当前后端 `/docs`。

## 9. 开发环境与复核命令

新 Windows 开发副本准备 uv、Node 22 和 npm 后，可运行 `./Setup-Project.ps1 -PythonExecutable 3.13`。显式选择项目支持的 3.13 系列，不复制已有虚拟环境；本机旧环境曾使用 3.14.6，服务器已验证 3.13.16。私有配置另行注入，不从 GitHub 获取。

```powershell
# 在项目根目录，使用隔离测试数据库，禁止误指向生产数据库
& ./.venv/Scripts/python.exe -m pytest ./backend/tests/test_care_management.py ./backend/tests/test_edge_storage.py -q

# 前端：进入 frontend 后运行
npm ci
npx tsc --noEmit
npx eslint src/app/login/page.tsx src/components/care-account.tsx src/components/care-management-home.tsx src/components/care-management-user.tsx
```

PostgreSQL 集成测试通过私有环境变量 `ROBOT_CARE_TEST_DATABASE_URL` 提供地址；测试器只接受回环地址和 `robot_care_test_` 前缀数据库，且会重建测试表。不能用生产数据库跑测试。前端构建需设置服务端 `BACKEND_URL` 为目标本地 API 地址；它不应指向数据库。

迁移工具拒绝覆盖已有目标数据。实际部署角色、数据库及密钥要由运维配置，不因拿到一份源码就自动连接生产服务器。
