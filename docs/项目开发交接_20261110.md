1. 开发交付可运行实现、自测与证据；计划、开发自测、独立验收、真实联调分开记录。

8. 使用项目独立环境，不改全局工具、科研环境、同事或并行工作区，不覆盖旧交付与验收证据。

### 两条链路必须分清

**本方主线：** 终态文本事件 → `robot_client.Outbox` 持久入队 → 上传 worker → `/api/robot-records` → SQLite → 独立 `app.care.worker` → `care_core` → 分析/策略表 → `/api/robot-insights` → `/robot-care` → ReportDTO → 预览/打印。

**原生对话：** `/chat` → `/api/chat/send` → coordinator / ConversationAgent → Ollama 适配 → SSE。没有证明它自动写入 robot-records，也未把分析页支持模板接入上下文动态生成。

“支持提示总是类似”的原因可定位到 `care_core/core.py::_choose_support`：按 positive/neutral/negative 或孤独、担忧分支选固定模板。即使配置模型分析引擎，支持文字仍来自模板；只改分类器不能解决动态回复。

## 5. 当前汇报底稿

### 5.1 三段对话

主账号共 3 个已关闭、收齐、`is_test=true` 会话，每段 4 条，用户/助手交替，共 12 条。

| 会话 | 固定用户文本 | 演示用途 |
|---|---|---|
| 日常积极 | “今天和朋友散步，我很开心。”“我很期待下一次见面。” | 积极分类、历史和报告 |
| 孤独担忧 | “最近孩子工作很忙，我感到孤独。”“我也很担心家人，最近压力很大。” | 孤独/担忧支持模板 |
| 明确危险表达 | “最近我觉得很难过。”“我不想活了。” | 醒目提示与人工核实 |

每段另有两条固定助手文字。时间在新运行时生成。危险表达仅测试案例。用户 playback 为 not_applicable，助手为 not_started，不伪造已经播放。`source='doubao_realtime'` 是现有 schema 枚举，即使在模拟记录中出现也不能证明豆包接入。

### 5.2 原始三条量表

它们是 `demo_wellbeing` 的三次**虚构展示结果**，不是 PHQ-9、GAD-7、PSS-10 三套真实答卷。

| 完成时间（北京时间） | 分数 / 范围 | scale_version / scoring_version |
|---|---|---|
| 2026-10-20 10:00 | 5 / 0—10 | demo-v1 / demo-v1 |
| 2026-10-27 10:00 | 7 / 0—10 | demo-v1 / demo-v1 |
| 2026-10-28 10:00 | 4 / 0—10 | demo-v2 / demo-v2 |

名称“虚构展示量表（非实际评估）”；解释版本 demo-draft-v1，状态 verified_fixture / demo_only / demo_draft，审核引用 demo:not_formal_review。源 ID 为 `fixture:user{uid}_1/2/3`，绑定主账号。独立 JSON fixture 存储，未写原生 assessment_records。服务端规范为 UTC，页面按北京时间显示。

demo-v1 两点可显示变化；demo-v2 一点提示不足，不跨版本凑趋势。原始日期、版本、分数保留，不伪装为今天真实测评。

**默认报告范围：** 无已保存范围时，起始月会向前覆盖本账号已验证演示量表的最早完成月，结束仍为下月月初。已保存范围保留，用户可改。指定会话不自动关联量表；同时看对话和量表应选覆盖它们的时间窗口。

### 5.3 现场新增

`/robot-care` → “新增演示对话” → `/robot-care/new`。每轮用户文字必填、助手可选，最多 20 轮；保存进入实际记录、规则 worker、历史与报告。

`POST /api/robot-insights/demo-conversations` 仅 development 且专用 demo 库开放。服务端强制测试属性、原子保存并关闭会话；按用户+request_id 幂等，同内容返回原会话，冲突 409，删除后不重建。它不是自动聊天接口。production 拒绝，不能为方便上线去掉保护。

## 7. 接口与数据语义

复用 `/api/auth/register`、`/api/auth/login`、`/api/auth/me`。携带 `Authorization: Bearer <JWT>`，服务端确定 owner，不接受 body 指定别人的用户 ID。敏感响应 no-store，错误不回显心理正文或凭证。

下表前缀为 `/api/robot-records` 或 `/api/robot-insights`：

| 前缀 / 方法与路径 | 作用 |
|---|---|
| robot-records：`POST/GET /sessions` | 建会话、本人签名游标分页列表 |
| robot-records：`GET/DELETE /sessions/{sid}` | 详情 / 删除及防复建 tombstone |
| robot-records：`POST/GET /sessions/{sid}/messages` | 不可变终态文本入库 / 按序号查询 |
| robot-records：`POST /sessions/{sid}/close` | 固定最终序号，允许上界内补传 |
| robot-insights：`GET /profile`；`POST /demo-conversations` | 匿名编号、演示入口 / 原子保存手动对话 |
| robot-insights：`POST /analysis-jobs`；`GET /analysis-jobs/{id}` | 建立/读取版本任务 |
| robot-insights：`GET /sessions/{sid}/analyses`、`/summary` | 分页分析与有效稿摘要 |
| robot-insights：`GET /messages/{id}/effective`；`POST /messages/{id}/corrections` | 原文/有效稿、幂等更正与冲突 |
| robot-insights：`GET /policies/{id}` | 来源、版本、有效期、模拟可用性 |
| robot-insights：`POST /strategy-deliveries/simulate`；`GET /strategy-deliveries/{id}` | 模拟接收/拒绝，不能标成真实 applied |
| robot-insights：`GET /assessments`、`/trends` | 只读量表、分组趋势 |
| robot-insights：`POST /reports/preview` | 临时 ReportDTO，供网页和打印 |

详细输入见 schema、实现和运行时 `/docs`；部分响应为通用 JSON，OpenAPI 不代表所有输出字段的完整契约。

### 7.1 上传与存储

- 会话唯一键 `(user_id,source,external_session_id)`；消息唯一键 `(session_id,external_message_id)` 和 `(session_id,sequence_no)`。重试沿用稳定 ID，不换号绕过冲突。
- 首次写入通常 201、相同重试 200、冲突 409；本人已删 410、他人 404；验证 422、存储忙/提交失败 503。内部 ID 限正整数 int64。
- 事务提交后才 ACK。本地 outbox 先落盘，独立 worker 发 HTTP。after_close 封存后才开始上传，旧默认 streaming 保留。
- `robot_client.Worker` 上传，`app.care.worker` 分析，是两种 worker。音频回调不能等待网络、重试或模型。
- closed 不等于收齐；收齐到最终序号才完整。文本 completed 不等于助手音频已播放完。
- 当前合法 playback_status 是 `not_applicable/completed/interrupted/not_started/unknown`，不要写未定义的 played。用户必须 not_applicable，助手必须为其余值。
- outbox 有 pending/sending/retry_wait/blocked_auth/dead_letter/paused_retry/acked。身份错误按目标地址+用户持久暂停；令牌不存入 outbox。

### 7.2 当前稿、任务与删除

原始转录不 PATCH。更正带 request_id/base_revision/content；保留原文、递增修订、使旧结果失效。正文 A→B→A 仍是新输入修订，不能仅按文字相等复用旧输入版本。

任务唯一性包含用户、记录、输入修订、引擎/版本、配置版本。租约与提交令牌阻断过期尝试。失败、排除、无法判断分别保存，不填成中性。配置 A→B→A 可恢复同一输入有效 A 结果，与输入正文修订 A→B→A 是不同问题。

删除需同事务清理更正、快照、任务/结果、策略/回执，旧 worker 不得复活。仅留必要 tombstone 与 owner 绑定 HMAC 的最小删除引用。SECRET_KEY 持久保管，换密钥会影响 JWT、签名游标及旧删除引用的可定位性。

### 7.3 量表与来源

provider 为 disabled/fixture/live。fixture 仅专用演示库，production 禁用。live 读取原生记录，但缺记录级版本、确认完成时间、范围、审核依据时仍为 unverified；不以当前模板补造历史，不重算。

当前未实施 `verified_test_submission` 接入，这是 2.5 计划要求。趋势按来源、量表/计分等版本和测试属性分组；至少两个独立有效点才展示变化，不给总体好转/恶化结论。is_test=false 仅是属性，不证明真实性或审核完成。混合来源逐条标识、分流统计，不整份简单标“全部模拟”。

### 7.4 报告与危险表达

scope 二选一，不能混用：

```json
{"scope":{"session_ids":[1,2,3]}}
```

```json
{"scope":{"time_from":"2026-09-30T16:00:00Z","time_to":"2026-11-30T16:00:00Z"}}
```

第二例为北京时间 2026-10-01 至 2026-12-01，左闭右开，只说明当前样例日期。对话按 occurred_at、量表按确认 completed_at。指定会话不猜量表关联。

报告临时组装，不长期保存正文。预览/打印用同一次重新读取来源的 DTO。`danger_notice` 扫描当前范围、当前 owner、user、completed 的**当前有效稿**，不依赖模型/任务完成。

明确危险表达列出触发表达、规则 ID、record_id、会话、发生时间、input_revision、测试属性。标题下方加粗边框，要求人工关注核实；打印不只依赖背景色。否认、引用、第三人转述或语境不明保守处理；普通消极和量表分数不触发。更正/删除立即重算，不沿用旧稿。未检出不代表无风险，不给临床等级或自动动作。
