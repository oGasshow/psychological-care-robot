## 当前使用

先阅读 [语音说明](../../features/voice.md) 与 [报告说明](../../features/reports.md)。继续本机数据使用 `Resume-Project.cmd`，登录后进入“语音陪伴”。点击开始才采集麦克风，结束并保存后可直接查看历史和生成本次回顾。量表开发继续停止；原只读页面与历史数据保留。

密钥仅配置于忽略的本机 `backend/.env`。仓库不携带用户提供的密钥、登录 JWT、原始附件代码、第三方 SDK PDF、数据库、运行账号或队列。其他电脑须按 `.env.voice.example` 配置并按锁文件安装；不要将真实配置复制回示例文件。

## 代码与接口

| 位置 | 用途 |
|---|---|
| `backend/app/voice/settings.py` | 服务端语音开关、密钥、地址与时限校验 |
| `backend/app/voice/upstream.py` | Seeduplex JSON 会话、真实云连接、报告函数调用 |
| `backend/app/voice/transcripts.py` | ASR/回复稳定 ID、去重、旧回复打断隔离 |
| `backend/app/voice/recording.py` | 复用 Outbox，结束上传、重试及用户隔离 |
| `backend/app/voice/api.py` | 登录鉴权的 `/api/robot-voice/config`、`/live`、`/retry-records` |
| `frontend/src/components/care-voice.tsx` | 真实浏览器收音、播放队列、字幕与会话控制 |
| `frontend/public/audio/pcm-capture.js` | AudioWorklet 转换为 16 kHz / 20 ms PCM |
| `device/voice_client.py` | 独立 Windows/Pi 终端，音频设备适配接口 |
| `backend/app/care/report_narrative.py` | 新增 `doubao_realtime`，保留其他文本 provider |
| `frontend/tools/voice-evidence.mjs` | 隔离库、虚构 WAV、真实浏览器与真实云验证 |

同源网页通过 Next.js 转发 WebSocket；JWT 在首帧发送，云端密钥始终留在后端。生产反向代理也必须转发 Upgrade。当前会话并发限制是单 worker 内每用户一条；多进程部署需另行实现共享会话锁。

## 本轮证据

Windows 独立运行目录使用 `runtime/voice_check_20261111_1615`，没有切换活动运行指针，也没有清空原演示库。测试正文全部虚构，输入通过 Windows SAPI 合成；未打开现场真人麦克风。

- 真实服务：鉴权、开场 TTS、用户转录、动态回复和音频均返回；完整单轮最终文字上传成功，报告 API 返回 HTTP 200 / `mode=model`。
- 多轮：同一会话完成三段不同语音输入，保存三条用户文字和含开场的四条助手文字，共七条；本次约 25.38 秒，返回 PCM 1189820 字节。
- 独立终端：`device/voice_client.py --wav --no-playback` 在 Windows 跑通，收到 `records.saved`，不依赖 PyAudio。Pi 声卡与 ARM 环境未验。
- 浏览器：Edge 157 使用假麦克风 WAV，已验证实际帧发送、音频调度/结束、手动打断、暂停/继续、停止麦克风、保存和移动端布局。人工浏览器截图核查已执行。
- 回归：全量 219 个测试与 31 个子项通过；后续语音专项共 13 项通过，与全量存在重叠。前端构建、TypeScript 和 lint 增量检查通过，未新增诊断。

## 交付边界

语音、动态模型回复、报告模型总结已真实调用。文字分类仍使用规则引擎；软件播放回调不等于真人听到，已入库助手播放状态保守为 unknown。报告使用同一语音权限的合成触发与函数调用，并非已开通普通方舟文本 API；千问/Ollama/方舟文本适配仍仅做本地协议验证。

接下来现场检查真人收音、回声、实际听感、长时间连续交流与网络抖动，再验证 Pi/机器人硬件和公司 HTTPS 部署。策略动作目前仍为原来的本地模拟器，没有擅自接入真实动作。报告质量与正式内容审核仍须人工评估。
