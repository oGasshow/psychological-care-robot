# 2026-11-12 开发修复交接

本轮处理三个实际反馈：用户原话旁缺少逐句情绪标签、“我有点不想活了都。”漏掉危险提示，以及后台量表页只显示旧模拟量表。

## 已完成

1. 逐条用户最终文字使用可配置的豆包语义分类；修复启动器强制 rules 的覆盖。会话原话旁显示积极／中性／消极及处理中或失败状态，助手回复不分类、不进入用户统计。旧规则与 Ollama 保留，历史记录按配置指纹重排，原话不改。
2. 明确危险表达规则补充有限第一人称修饰，排除否认、引用、他人转述与明确假设。会话摘要、对应原话和报告顶部独立显示提示，不等待模型完成；转录更正、删除、用户隔离及报告范围均生效。实时语音遇到该表达优先停止量表采集。危险提示与消极情绪并行，不输出临床等级。
3. 后台量表页接入 conversation_collections，显示最近 100 个语音记录会话的进度和已确认条目。原 fixture items 保留但默认折叠；对话辅助合计、模拟分数、历史正式来源分开，缺项不补零，未齐不出总分。
4. 新增独立进度回执表 robot_voice_collection_traces。普通会话不创建空 PHQ-9/GAD-7 结果；回执仅记阶段和检测状态，用于说明未触发、等待时机、采集中、暂停及安全优先等情况。旧会话未保存回执时不倒填原因或分数。
5. 已确认条目必须能定位到原始用户频率表达、用户确认和助手话题复述；原话更正、依据缺失或超出报告范围时隐藏辅助合计，标为待重新核实。旧语音结果 API 与后台页面采用同一核查口径。

## 配置、运行与数据

本机 backend/.env 使用 ROBOT_CARE_ANALYSIS_ENGINE=doubao_realtime、ROBOT_CARE_SENTIMENT_TIMEOUT_SECONDS=45，凭证沿用现有服务端配置且不入库。模型不合规输出按既有 worker 上限重试，默认最多三次，最终失败不会补作中性，独立风险提示仍可用。

继续现场数据使用 Resume-Project.cmd；Start-Presentation.cmd 会创建另一个固定演示库。此次使用原 active_runtime 继续运行，没有清库：更新前后均为 5 个会话、40 条消息、0 条更正。当前库的 19 条用户记录已完成真实豆包重新分类，助手 21 条不参与。

这些会话包含虚构启动基线及测试环境语音记录。测试环境标志不等于该条数据就是旧 fixture 量表；页面对话采集来源与 fixture 明确分列。密钥、运行账号、数据库、个人原话和运行截图均不提交 Git。
