# 心理疏导机器人使用手册

更新日期：2026年11月23日。本手册适用于当前用户端、管理员端及九区评估报告。普通用户先看第2至6节，管理员看第7节，安装和维护人员看第8至11节。历史交接文件保留当时的版本记录，操作与报告口径以本手册及对应功能说明为准。

## 1 系统分工

| 使用者或组件 | 入口或运行位置 | 职责 |
|---|---|---|
| 普通用户 | 树莓派或本机浏览器 | 登录、语音陪伴、量表续答、查看和导出本人报告 |
| 管理员 | 服务器管理员网页 | 查看用户报告、查看待联系提醒、记录人工跟进 |
| 终端后台及分析进程 | 树莓派或开发电脑 | 语音连接、记录上传、辅助分析、采集任务和报告取数 |
| PostgreSQL | 服务器 | 统一保存账号、个人资料、对话、答案、进度、结果和管理审计 |

同一账号可以有多段对话，量表进度可以跨会话延续；不同普通账号的数据按登录身份隔离。管理员必须单独授予权限，普通注册不能变成管理员。

本地用户网页可以使用本机 HTTP。终端通过受限 SSH 连接服务器数据库；不能把数据库密码或豆包密钥填到浏览器。正式终端需要服务器网络连接，不承诺离线对话也能持久保存。

## 2 启动和登录

### 开发电脑

在已有环境的项目根目录双击 `Open-NormalMode.cmd`。它启动普通模式并保留已有数据，优先使用 Chrome。不要用“新建演示”入口代替日常启动。

当前开发电脑的用户入口为 `http://127.0.0.1:51078/login`，后台为 `http://127.0.0.1:51077`。其他机器的端口以启动器实际输出为准。原目录为 `D:\project01`，更换电脑后不要直接照搬 Windows 虚拟环境。

第一次安装可先运行根目录 `Setup-Project.ps1`，再按[快速开始](getting-started.md)准备依赖和配置。普通模式连接服务器时，还需要负责人提供的私有连接材料，不能只复制网页代码。

### 树莓派

安装完成后，在树莓派本机 Chrome 或兼容浏览器访问 `http://127.0.0.1:3000/login`。手机上的 `localhost` 指手机自身，不能用这个地址访问树莓派。

### 登录和退出

已有账号输入用户名和密码后登录。普通用户进入个人空间；管理账号应从服务器管理员入口登录。共享设备使用完后点击“退出登录”，不要让下一位使用者沿用账号。

## 3 注册和个人资料

注册时填写用户名、密码和确认密码，并登记紧急联系人姓名、电话，确认已获得联系人的同意。紧急联系人为必填项；姓名或称呼、性别和年龄可选填。年龄填写1至120的整数，联系电话填写可用的手机或固定电话号码。

姓名和用户编号、性别、年龄、紧急联系人会用于本人及授权管理员查看的报告。报告时间、对话段数、用户发言数、经过时长和转写状态由系统生成，不需要在注册时填写。

老账号仍可登录和查看历史报告。开始新的语音对话前，如果提示缺少联系人，请进入导航栏“个人资料”，补齐联系人并保存。个人资料入口为 `/robot-care/profile`，只修改当前登录账号，不能代替他人填写。

未填写的可选资料显示“未提供”。系统只检查电话号码格式，目前不验证号码真实性或能否接通。普通注册不能授予管理员权限。

## 4 语音陪伴

1. 登录后进入“语音陪伴”。先确认紧急联系人已补齐。
2. 选择音色和语速。音色和语速在新的通话开始时应用。
3. 点击开始，按浏览器提示允许麦克风。检查收音和扬声器，必要时使用耳机。
4. 正常交流；字幕显示识别后的文字。系统会在适合的时机了解与近况相关的问题，用户可以暂停或停止回答。
5. 结束时点击“结束并保存”，或使用明确结束表达，并等待保存结果。

当前提供四种音色：

| 音色标识 |
|---|
| `zh_female_qinqienv_uranus_bigtts` |
| `zh_male_tiancaitongsheng_uranus_bigtts` |
| `zh_female_xiaohe_uranus_bigtts` |
| `zh_female_wenroumama_uranus_bigtts` |

如果页面提示记录仍待同步、保存失败或未收齐，请按页面提示重试，不要把这种状态理解为已经完整保存。终端未确认的数据可能只在内存中；不要直接断电或强制关闭服务。语音错误和网络问题不会被当成“用户状态正常”。

## 5 量表采集与跨次续答

普通模式支持PHQ-9和GAD-7的对话辅助采集。系统根据实际线索选择要了解的方向，不要求每段聊天都填写全部条目。已经确认的回答与任务归属保存到服务器。

例如：第一段正常聊天；第二段出现需要进一步了解的线索；第三段只完成部分问答；第四段在合适时继续未答内容；本轮完成后，第五段可以恢复日常交流。用户仍可以暂停或停止，新的会话不应无故清空未完成任务。

在“我的量表”查看已确认条目、完成进度及参考结果。不同采集任务、不同固定回顾窗口和不同账号的答案不能拼在一起。更正原话或删除会话后，相应答案和报告需要重新核对。

SEGA是辅助实验链路，`class=1`不等于确诊，`class=0`不等于排除风险。软件流程测试通过也不代表已经验证真人筛查效果。当前能力边界见[报告后台检查](features/report-backend-audit-2026-11-23.md)与[SEGA说明](features/sega.md)。

## 6 查看和导出报告

打开“报告摘要”或 `/robot-care/report`，选择一段已结束且记录完整的对话，再选择范围：

| 范围 | 纳入规则 |
|---|---|
| 本次对话 | 仅选中的完整会话及其有效记录 |
| 近三天 | 生成前72小时内开始、已结束且记录完整的同账号会话 |
| 近七天 | 生成前168小时内开始、已结束且记录完整的同账号会话 |

时间按北京时间显示，测试与非测试记录分开。多日报告用所选会话决定数据类别，不会把演示数据混入业务报告。

点击“更新并打印 / 保存 PDF”，在Chrome打印窗口选择“另存为PDF”。使用A4纸张、缩放100%，按页面打印样式保留背景颜色；浏览器额外的页眉页脚可关闭。先检查打印预览，内容较长时允许自然分页，不要靠裁切挤成一页。

### 报告九个部分

| 部分 | 内容和解释 |
|---|---|
| 01 评估流程概览 | 展示对话、辅助筛查、问答及报告流程 |
| 02 基础信息 | 登记资料与系统统计；“转写完成”只表示文字已收到，不代表识别准确率已验证 |
| 03 量表评分 | 综合分及按完成率表示的“置信度”，下方小字说明分段 |
| 04 量表问答概况 | 只列范围内实际使用的量表，每种显示最近任务进度，不预填全部量表 |
| 05 情绪变化趋势 | 多日报告每段会话一个点；本次对话按用户发言顺序展示 |
| 06 对话风险信号 | 当前原话规则与已确认答案中的相关线索，未勾选不等于排除风险 |
| 07 关键对话摘要 | 情绪与生活状态、睡眠与兴趣、日常功能的相关原话摘录；没提供就写信息不足 |
| 08 分级建议与处置 | 结合分数、表达变化和具体线索的关怀建议；安全线索优先人工核实 |
| 09 继续完成量表 | 保留扫码区，目前手机续答入口待配置；在原设备用同一账号继续 |

### 分数与置信度

后台使用PHQ-9九项与GAD-7七项的16项综合口径，满分48分。完整时求和；部分作答按项目规则估算，无有效答案时显示“—”。参考分段为：低于10分正常参考或极轻微，10至不足20分轻度，20至不足30分中度，30至48分重度症状参考。

“置信度”实际表示有效已答题数占16题的比例：高为80%及以上，中为50%至不足80%，低为不足50%。它不是医学准确率、患病概率或诊断。仅完成PHQ-9的9题时，综合完成率是56.25%；未采集的GAD-7不能补作0分。不同独立任务不拼分。

### 情绪曲线

积极、中性、消极表达分别映射为100、50、0，多日报告在每段会话内取有效分类的平均值。没有有效分类的会话留空并断线，只有一个点就不连线。不同分析引擎或版本不混成一条曲线。

这是一种表达参考指标，不能直接当作连续情绪强度或病情程度。第6、7部分目前主要采用上下文规则、主题词和原话摘录，复杂隐含表达仍可能漏掉，不能保证完整语义理解。

## 7 管理员操作与待联系提醒

在当前开发电脑双击 `Open-ServerReports.cmd`，或使用负责人提供的管理员访问包运行 `Open-Reports.cmd`。当前通过受限连接访问服务器网页；没有已交付的微信小程序或原生App。

1. 使用已获授权的管理员账号登录，进入用户报告列表。
2. 选择业务记录或测试记录，按账号搜索用户，打开用户报告。
3. 选择本次、近三天或近七天，查看、刷新并导出PDF。
4. 留意页面的“待联系提醒”，需要时优先人工核实用户当前状况并联系登记的紧急联系人。
5. 实际完成相应人工跟进后，再点击“确认已人工跟进”。不要把点击按钮当作已经联系或已经确认安全。

### 提醒的工作方式

明确第一人称自伤或自杀表达、或已确认PHQ-9第9项提示需关注时，可产生待联系提醒。页面每30秒检查一次已保存记录，对话尚未结束也可出现；记录还没上传时，服务器无法及时检测。

提醒显示账号、相关会话时间和已登记联系人。系统不会自动发短信或拨打电话，页面关闭时也没有独立消息推送。管理员须安排值守和人工联系流程。若联系人尚未补全，不能假定系统已有可联系的号码。

人工确认记录按当前来源保存。同一来源不会重复显示待处理；新增风险表达或来源更正后会重新核对，删除记录后不继续展示已失效提醒。管理员不能在该端填写量表、删除用户记录或任意编辑关怀标签；新增的人工跟进确认是受权限保护的特定操作。

## 8 停止服务与常见问题

开发电脑先等待当前对话保存，再运行根目录 `Stop-Project.cmd`。不要用结束所有Python或Node进程的方式停止，以免影响其他项目。

| 现象 | 处理方法 |
|---|---|
| 提示先补齐联系人 | 打开“个人资料”，填写联系人及同意确认，保存后重新进入语音页 |
| 注册失败 | 检查用户名、密码、联系人姓名和电话、同意确认及网络；用户名不能重复 |
| 麦克风不可用 | 检查Chrome站点麦克风权限、系统输入设备及其他程序是否独占设备 |
| 提示语音未配置 | 由维护人员检查终端私有豆包配置和网络，不在聊天或公开仓库粘贴密钥 |
| 服务器数据库暂不可用 | 检查网络和受限连接，保留页面提示；不要切回本地空库代替正式数据 |
| 报告不能生成 | 等待会话结束且记录收齐；检查是否选了本人会话及正确数据类别 |
| 分数“—”或完成率很低 | 检查是否有已确认答案、所选范围是否包含来源、是否属于同一采集任务 |
| 曲线空白或断开 | 该会话可能没有有效分类、分类失败或口径不一致；不能补成“正常” |
| 摘要显示信息不足 | 用户可能没有提供相关信息，不应靠补造文字填满模板 |
| 没看到预期提醒 | 核对业务／测试范围、记录是否上传、是否属于明确本人表达、是否已经人工跟进；不能以没有提醒证明无风险 |
| 管理员不能进入用户语音页 | 这是角色隔离；管理员使用服务器报告入口，普通账号使用终端入口 |

常用服务检查和部署路径见[终端与服务器部署](operations/edge-central.md)。持续报错时记录发生时间、页面提示及已结束会话的状态，由维护人员查看对应服务日志；不要公开用户原话、联系电话或凭据。

## 9 新开发者从GitHub接手

仓库：[oGasshow/psychological-care-robot](https://github.com/oGasshow/psychological-care-robot)。先取得最新源码：

```bash
git clone https://github.com/oGasshow/psychological-care-robot.git
cd psychological-care-robot
```

依赖基线为Python 3.13及以上、Node.js 22；以 `backend/pyproject.toml`、锁文件和前端 `package-lock.json` 为准。Windows安装与启动见[快速开始](getting-started.md)。新机器必须重建依赖和前端，不复制另一台机器的 `.venv` 或 `node_modules`。

公开仓库包含源码、使用手册、测试、配置示例和报告参考模板，不包含真实密钥、数据库和私有安装包。模型权重已经放在公开的[模型交接附件](operations/model-release.md)，按清单校验后放到目标设备配置的位置。

已获服务器运维权限的接手人，可按[私有运行资料取得说明](operations/private-runtime-handoff.md)运行：

```bash
python tools/fetch_private_handoff.py --host SERVER_IP --user SSH_USER
```

工具会交互式询问密码，校验服务器身份和归档校验值，下载到本机忽略目录；不会自动解压或覆盖运行环境。负责人另行提供运维登录信息。私有归档是打包时快照，不是实时数据，也不能用其中旧源码覆盖最新GitHub版本。

管理员账号授权只由部署负责人操作。现有 `backend/tools/manage_reports.py --runtime` 入口按本地SQLite运行资料设计，不能拿终端配置直接当服务器管理员授权命令。中央PostgreSQL账号授权需使用数据库所有者的运维流程，不能给终端账号开放管理权限。

## 10 树莓派安装和服务器升级

在64位ARM Raspberry Pi OS上使用最新源码和已获授权的私有终端材料重新打包，不能直接把Windows环境复制到树莓派。打包工具为：

```bash
python tools/package_edge.py --private-dir PRIVATE_DIR --output-dir runtime/bundles
```

私有目录需要终端环境、连接配置、设备密钥和已核验服务器主机密钥；具体文件见[部署说明](operations/edge-central.md)。在生成的树莓派包中执行：

```bash
sudo bash deploy/edge/install-edge.sh
```

安装器还需要包内导出的 `requirements-server.txt` 和私有目录。不要在只有裸源码、缺这些文件时直接运行安装器。

安装后检查 `robot-care-edge-tunnel`、`robot-care-edge-api`、`robot-care-edge-worker`、`robot-care-edge-web` 四项服务，再从本机浏览器验证收音、播放、打断、保存、量表续答和报告。真实树莓派整机、长时间稳定性及SEGA ARM推理仍需目标设备验收。

升级已有服务器时先备份，再使用数据库所有者权限准备资料表：`backend/tools/migrate_user_profiles.py`；`--check`只检查是否存在。为终端账号授予新表受限读写权限，为报告账号授予读取权限，不修改旧用户密码和历史记录。当前服务器已经完成该步骤。

中央服务目前运行在 `/opt/robot-care-central/app`，服务名为 `robot-care-central-api` 和 `robot-care-central-web`。分析进程运行在终端，中央服务器不运行模型推理。应用更新后应重新构建前端并重启对应服务，再核验登录、报告和提醒；只更新GitHub不会自动更新另一台机器。

## 11 交接验收与待完成任务

接手时用独立测试账号确认：

1. 新注册要求联系人，老账号可以补填，其他账号不能读取资料。
2. 正常聊天、出现关注线索、分两次完成问答、下一次自然聊天的流程可继续。
3. 本次、72小时和168小时报告范围正确，同一天多段会话分别成点，缺失分类不补正常。
4. 量表进度、综合分、完成率和PDF取数一致；其他任务不混分。
5. 明确安全表达产生管理员待联系提醒，人工确认按来源记录；更正或删除后不残留旧结果。
6. 网络中断和重启时保存状态明确，既有服务器数据未被新环境覆盖。

优先待办为第6／7部分语义复核与独立标注评估、真人误报漏报评估、树莓派整机与SEGA输入一致性验证、管理员值守和人工联系演练。手机扫码续答、小程序、原生App及短信／自动外呼尚未交付。

本版保留113项回归检查、41项PostgreSQL隔离检查及7项页面检查结果，范围存在重叠，不能相加作为全项目测试总数；不等于临床有效性或所有部署环境已验收。详细证据和实现边界见[后台审查说明](features/report-backend-audit-2026-11-23.md)。
