# 注册资料与报告基础信息

注册页姓名／称呼、性别、年龄可选填；按最新要求，紧急联系人姓名、电话及同意确认改为必填。登录仍使用原用户名、密码。年龄为 1–120 的整数，姓名最多 50 字。联系电话进行格式校验，尚不验证号码的真实性或可接通性。

姓名、性别、年龄、联系人来自用户填写；用户编号、报告起止时间、生成时间、会话数、有效发言条数、经过时长和转写状态由系统生成，不要求用户在注册时填写。未填写资料显示“未提供”，不会猜测或阻止旧账号登录。

## 存储与升级

- 资料独立保存在服务器 PostgreSQL 的 `user_report_profiles` 表，以 `user_id` 关联 `users`。没有向旧 `users` 表增加必填列，不修改用户名、密码、历史对话或量表记录。
- 新账号和资料使用同一事务保存；资料写入失败时，整个注册回滚。重复用户名仍返回明确提示。
- 原有账号不会凭空补造资料，未提供资料的旧账号继续正常登录并生成报告。
- `GET /api/auth/me` 新增 `report_profile`，仅返回当前登录账号资料；不接受指定他人账号读取。用户／管理员报告按既有归属和管理授权展示报告对象的资料。
- 管理员用户列表不返回姓名和联系电话；资料不送入模型提示。报告来源哈希包含所展示的资料，资料变化时旧报告标识失效。

首次升级由数据库所有者在服务器执行 `backend/tools/migrate_user_profiles.py`（数据库地址通过私有环境变量配置）。脚本仅新增资料表，可重复执行；`--check` 仅检查表是否存在。单机 SQLite 使用相同模型，启动时可自动新建表。

服务器已有受限终端账号时，还须为新表授予终端账号 `SELECT, INSERT, UPDATE, DELETE`、报告只读账号 `SELECT`。不得为了资料表开放管理员授权表或旧账号密码的修改权限。旧 SQLite 迁移工具兼容不含此表的历史库，目标资料表初始为空。

旧账号可在 `/robot-care/profile` 补填资料；`PUT /api/auth/profile` 只修改当前登录普通账号。旧账号仍可登录查看历史报告，但开始新的语音对话前需补齐已获同意的联系人，页面和语音接口均检查。管理员不通过此入口修改他人资料。生产默认启用 `ROBOT_CARE_REQUIRE_EMERGENCY_CONTACT=true`；独立旧版测试夹具可显式关闭，不改变正式注册必填校验。

## 本次验证

注册资料、原注册兼容、报告与终端角色相关检查 59 项通过；真实服务器的独立 PostgreSQL 测试库 26 项通过（范围重叠，不相加）。Chrome 7 项检查通过，覆盖联系人校验、手机布局、新注册登录、资料往返、报告自动填充、管理员查看和跨账号隔离；虚构资料 PDF 已检查为一页。

服务器已新增资料表并授予终端受限写权限／报告只读权限，升级前后原用户表校验一致。本地普通模式与服务器管理员服务均已更新。生产存储权限探针在事务内验证后回滚，没有留下测试账号；其他界面测试使用独立测试数据库。
