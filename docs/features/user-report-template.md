# 用户评估报告与 PDF 模板

2026-11-23 接入。设计参考保存在 `docs/templates/user-report-reference.docx`，运行时由共享 HTML/CSS/SVG 生成预览和打印 PDF，不依赖用户桌面文件或 Word。

## 使用

用户进入 `/robot-care/report`，选择已结束的对话，再选择本次对话、近三天或近七天。管理员在用户报告详情页作相同选择。“更新并打印 / 保存 PDF”先读取最新来源，再打开浏览器打印。界面和 PDF 使用同一份报告数据；内容较长时自然分页，不能截断隐藏。

按最新要求，近三天／近七天分别为生成时刻前 72／168 小时。按会话开始时间纳入窗口内已结束且记录收齐的对话，测试属性分开；未结束、已删除或窗口外的会话不纳入报告。时间显示使用北京时间。

## 九个报告区域

1. 评估流程概览。
2. 基础信息：注册时选填的姓名／称呼、性别、年龄及已获同意的联系人，另显示系统编号、范围、时刻、会话数、有效发言数、经过时长、转写完成／失败／待核对。未提供资料保留缺省，不猜测。转写状态不是语音识别准确率。详见[注册资料与存储](registration-profile.md)。
3. 两个数值：综合量表分与置信度；仅在下方小字解释区间和局限。
4. 按需展示范围内实际使用的量表，每种量表显示最近一次任务的进度，包含已开始提问但未确认答案的情况，不预填全部量表。综合分只采用最新同一任务，不能把不同任务拼满。
5. 情绪变化趋势：本次按有效用户发言顺序，多日报告每个会话段一个点，按开始时间排列。无有效分类的会话为 null，断线；单点不连线，不补作中性。
6. 风险线索：已确认量表答案或当前用户明确自述；否认、他人转述、假设不默认勾选。安全关注单独处理。
7. 情绪与生活状态、睡眠／兴趣、日常功能三类摘要。按完整范围搜索用户原话，保留来源编号；缺失明确写信息不足，不依据量表注意力条目推断工作受损。安全危险原话不复制到普通摘要中。
8. 关怀建议结合综合分、消极表达分布、先后变化和具体线索；明确安全线索优先，管理员收到人工联系提醒，不自动发送短信或拨打电话。
9. 扫码区保留“续答入口待配置”，不生成无效二维码；当前使用原设备同一账号。

## 后台计算

综合分采用 PHQ-9 九项与 GAD-7 七项的 16 项、0–48 分口径。完整作答直接求和；未完成时，按用户要求采用 `已答小计 × 16 / 已确认题数` 的项目估算，保留一位小数；0 题不估算。分段按未舍入的数值比较 10、20、30：正常参考／极轻微、轻度、中度、重度症状参考。完整分段出处为 [PHQ-ADS 原始研究](https://pmc.ncbi.nlm.nih.gov/articles/PMC4927366/)，DOI 10.1097/PSY.0000000000000322。对话采集和缺失题外推未在本项目获得同等验证，不作为诊断，也不改变现有用户风险标签。

“置信度”按约定显示为 `有效已答题数 / 16 × 100%`，高为 ≥80%，中为 ≥50% 且 <80%，低为 <50%。这是项目完成率分档，不是经过校准的准确率或患病概率。自定义对话指标保留独立完成情况，不纳入 16 项综合分。

只在同一账号、同一测试属性、同一采集任务及固定回顾窗口内合并。重复条目取较新有效答案，独立任务不能拼接。报告选择多日范围时展示范围内最新任务；单次报告只使用本次消息支持的答案。更正、删除或范围变化会重算并更新来源哈希。

情绪分是独立的表达参考指标：消极／中性／积极分别映射为 0／50／100，多日报告在每个会话内部对有效分类取平均。本次未分类发言保留缺口。不同分析引擎或版本不混成一条线，采用范围内最新的有效分析口径；未分类、失败和失效结果不视为中性。不用综合量表分或 SEGA class 当情绪分。

## 接口与兼容

- 用户：`GET /api/robot-insights/reports/template/{sid}?period=session|three_days|week`。
- 管理员：`GET /api/care-management/template-reports/{sid}?period=session|three_days|week`，继续核验管理员授权并记录访问审计。
- 旧单次报告、旧窗口汇总及旧摘要生成接口保留，现有客户端可继续调用。
- 无数据库结构迁移；数据仍在既有服务器数据库中，中央服务不执行模型推理。
- 管理员待联系提醒：`GET /api/care-management/safety-alerts?is_test=false&limit=30`；人工确认：`POST /api/care-management/safety-alerts/{sid}/acknowledge`，提交当前 `source_hash`。只把人工跟进写入原访问审计表，原安全线索不被清除；来源变化后原确认不能覆盖新风险。中央服务只额外允许这一受管理员鉴权保护的写操作，其余业务写接口仍关闭。

主实现：`backend/app/care/template_report.py`、`backend/app/care/composite_score.py`、`frontend/src/components/care-report-template.tsx`。评分、图表、信号和摘要均从当前有效来源生成，页面不自行外推分数。
