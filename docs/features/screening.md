# 按需触发的对话辅助采集

按当前产品流程，心理信息整理与后台辅助评分用途由购买须知说明。会话中没有勾选、口头同意、“准备好了”、题号或答题进度。普通用户只进行自然陪伴，只有后台上下文检测给出有依据的进一步了解决定，才安排相关条目的对话采集；没有结果的报告不显示量表模块。

## 运行流程

`自然陪伴 → 后台上下文检测 → 无需进一步了解则继续陪伴；需要了解则等待合适对话时机 → 豆包自然衔接话题 → 澄清与核对信息 → 后台辅助合计 → 报告按实际结果显示`

每个语音会话先保持 companionship。累计至少三个不同的最终用户回合后启动后台检测，随后每新增两个用户回合更新一次；最多保留最近二十四条用户/助手文字作为上下文，一次只执行一个检测，待处理输入合并为最新快照，不阻塞音频转发。若检测过程中来了新用户内容，可以沿用已有线索，但不把旧结果的“适合过渡”用于新状态，会重新检查最新上下文。

检测器区分 no_signal、monitor、follow_up，结合提问与回答，区分本人自述、否认、转述、假设和短暂日常情绪。follow_up 必须有至少两个不同用户消息中的逐字证据，以及持续时间或生活影响；按依据选 PHQ-9、GAD-7 或两者。仅有“当前可以交流”不会触发量表。无效引用、格式错误、服务失败、信息不足时均不强行启动采集，也不退回关键词强制触发。

有线索也不等于可以立刻询问：后台只在最新对话适宜温和过渡时进入 collecting；这不是临床“情绪稳定”判定。用户不适时暂停、明确拒绝则本次停止；危险表达优先处理支持需求，不通过问卷确认或降低危险提示。

## 购买须知配置

在忽略的本机 backend/.env 或部署进程环境中配置：

```dotenv
ROBOT_CARE_GUIDED_SCREENING_ENABLED=true
ROBOT_CARE_PURCHASE_NOTICE_VERSION=your-purchase-notice-version
ROBOT_CARE_CONCERN_DETECTOR=doubao_realtime
```

notice_version 是部署方对购买须知覆盖本功能的版本声明，作为来源元数据保留；本仓库不实现销售、付款或逐用户购买记录验证，也不把它伪称为已经核实的个人签署记录。不再由网页的 guided_screening 字段授权功能，旧客户端的该字段只兼容接收，不控制是否触发。未配置有效版本时不启用采集。

当前本机已配置项目声明版本。首次部署其他电脑时需按实际购买须知设置版本，不把示例占位符当成真实版本。修改后重启 API；已有运行数据使用 Resume-Project.cmd，不清空原库。

## 如何通知当前豆包会话

通过当前连接的 session.update 下发阶段、待补信息和话题指令，session.updated 才表示云端确认收到；排队返回不算已经生效。普通阶段明确要求自然陪伴，不执行固定条目采集。触发阶段每次只自然衔接一个话题，不报量表名、题号或要求同意；用户询问用途时如实说明，不否认后台信息整理。

独立检测模型也可向本人当前会话发送线索，不能注入自定义提示词、地址或分数：

```http
POST /api/robot-voice/screening-signal
Authorization: Bearer <记录所属用户的系统JWT>
Content-Type: application/json
```

```json
{
  "session_id": "voice_当前会话ID",
  "evidence_ids": ["当前会话内真实最终用户转录ID"],
  "detector_version": "your-detector-version",
  "target_scales": ["PHQ-9"]
}
```

它先标记需要进一步了解，不能跳过对话时机判断。当前内置上下文检测仍会检查最新表达。跨用户、错误会话、虚构引用及队列拥堵被拒绝。Windows 网页和 Pi 使用相同的服务端流程，不需持有云密钥或额外传入用户同意标志。

## 答案与报告

两套回顾窗均为最近两周。频率不明确时温和澄清，待确认值只接受明确频率表达；不会从普通情绪词、模糊描述或未知条目猜分。计分前必须有助手实际复述当前话题、两周时间范围和对应频率，并获得用户确认。保留用户频率表达、确认及助手澄清的消息 ID；下一话题不复用旧确认。

结果逐项 0—3，缺失为 null，全部条目齐全才给辅助总和；结果固定 conversation_assisted / unverified / formal_assessment=false，不生成诊断或临床分级。PHQ-9 自伤相关项非零暂停后续采集。当前抽取器较保守，自由表述可能需要澄清，不能据此宣称已验证与标准量表等效。

未触发的普通会话不写空 PHQ-9/GAD-7 结果。报告 preview 的 conversation_assessments 为空，网页和打印都没有量表区块，不提示普通用户补做问卷。旧版本留下的全空条目也不显示。触发但尚无已确认条目时仍不展示空分数；有已确认信息后，独立显示实际目标量表的辅助结果。它们不混入正式量表趋势或模型叙述事实包，更正原话后仍需核实。

结果在最终文字经既有 Outbox 保存后写入 robot_voice_screening_results；本人可读取，删除原会话同步删除辅助结果。失败单独提示，不误报已经保存的文字失败。当前不支持跨会话恢复尚未完成的采集，原话补传不等于采集状态恢复。

上段的“尚不支持跨会话恢复”是此前版本边界；本次已由以下任务机制替代。

## 跨会话任务

robot_voice_collection_plans 按本人账号及测试属性保留 needs_collection、目标量表、已确认条目、固定回顾范围、阶段与依据。识别到需进一步了解、明确危险表达或有完整来源的 SEGA 实验关注信号时建立待继续任务。普通闲聊、换通话、无新线索、模型class=0均不清除任务；全部目标条目有已确认信息才自动完成，后续通话回到自然陪伴。用户停止或不适时尊重暂停，不靠持续追问凑齐信息。

重连先补传既有 Outbox，再恢复任务；同一回顾窗口的已确认项不重复问，新的通话先核查当下是否适宜继续。有历史危险表达时先 checking_in，不因一句“好了”宣布安全，也不用问卷确认安全。任务标识不是诊断或“当前一定危险”的结论。

最近七天、最多五段本人的实际 voice_ 会话可提供有效稿背景，排除固定演示基线、已删除、未完成及其他用户/测试属性。保留重要危险表达锚点，避免被后续寒暄挤掉；任务本身不会因七天背景窗口到期被自动清除。已完成任务之后的历史选择从完成时间起算，避免旧表达立即重新创建同一任务。

频率抽取新增真实豆包结构化调用，可理解“三四天”“大多数日子”等自然表达；必须逐字定位实际问题、用户回答、已说过的两周范围及频率。候选只显示待核对，仍需自然复述和用户确认才入项，缺范围/频率显示待补。“最近有什么轻松小事”本身不对应具体条目，不能直接加分，应继续温和澄清具体经历。采集进度会区分候选信息和已确认信息。

源依据缺失或被更正时需要重新核实，不能默默沿用旧分；固定回顾范围超过14天时保留任务标识，但清理过期候选项并重新锚定回顾范围。删除相关会话会同步清理关联任务及模型结果。任务接口 `GET /api/robot-voice/collection-plan` 仅本人可读，后台量表页展示未完成任务。

2026-11-12：后台“量表与对话采集结果”已接入实际对话辅助采集来源，不再只读旧 fixture。`GET /api/robot-insights/assessments` 的原 items/provider 保留，新增 conversation_collections 单独提供最近 100 个语音记录会话的进度及已确认条目；模拟量表默认折叠，辅助合计不混入正式量表统计。

新增 robot_voice_collection_traces 仅保存会话结束时的阶段与检测状态，不创建空 PHQ/GAD 结果。可区分自然陪伴、等待时机、采集中、暂停、用户停止、安全优先停止及完成；旧会话没有进度回执时如实标注“未保存采集结果”，不臆测当时未触发的原因。结束后刷新页面读取结果；尚未结束的状态仍通过语音页联调信息查看。

已确认条目关联原始用户表达、确认和助手复述的消息 ID。缺少依据、范围外依据或原话更正时隐藏辅助合计并要求重新核实；未确认和未完成不补分。删除会话同步删除进度回执与辅助结果。当前抽取仍需要明确频率和话题复述确认，不能从普通消极表达直接生成两套量表总分。

## 当前方法与论文

[Chen 等，NAACL 2024，SEGA](https://aclanthology.org/2024.naacl-long.452/) 使用访谈问题与回答文字/音频/视频的结构图进行抑郁识别，LLM 用于数据增强。本轮参考其利用问题—回答上下文整理线索的思路，接入可实际调用的豆包结构化上下文检测器，不是训练或复现 SEGA，也没有论文的多模态模型、性能或临床阈值。

后台检测复用已开通的实时语音权限，在独立后台会话中以固定合成语音触发结构化工具结果，不打开麦克风/扬声器，不写入用户对话。它是决定是否进一步了解的工程原型，不能当作抑郁诊断或已经完成测量有效性验证。

量表口径参考 [NIH PHQ-9](https://www.nih.gov/node/19946)、[NIMH GAD-7 数据字典](https://nda.nih.gov/data-structure/cde_gad701)。正式使用仍需核对中文版本与适用人群，并评估对话采集相对标准施测的差异、漏项、错误归因与实际体验。

## 可复核检查

### 怎么观察是否触发

不使用“你什么时候让我答问卷”等功能询问作为触发口令，这类假设不构成用户自己的症状。当前首次检测至少需要同一通话中三个不同的最终用户回合；之后还有后台推理等待时间。不要在第三句话后立刻结束通话。判定是否触发、指令是否生效以后台状态为准，不能据豆包的一句能力自述判断。

本地测试页面可展开“开发联调状态（仅测试环境）”，点击“查看后台状态”，区分段数不足、检测中、未触发、等待过渡、正在采集以及云端指令回执。对应本人只读 API 为 `GET /api/robot-voice/diagnostics`，不返回密钥、原话或模型私有推理，也不调用模型。生产页面不显示此联调区。

开发联调可在专用虚构会话中分三轮说明“最近两周持续低落、兴趣减少”“已影响睡眠或日常生活”“聊过之后缓解一些，还想继续聊日常”，等后台完成后检查 collecting 和指令回执。它是演示数据，不应冒充自己的真实经历，不保证固定三句话一定触发；真实交流应如实描述。

语音会话创建时就下发当前阶段提示，后续再动态更新，避免旧的“永不主动询问”或“必须用户主动提出”口径影响回答。不能诊断与可以依后台安排自然追问是不同的能力。

- backend/tools/check_conditional_screening.py：只用虚构文字实际调用检测服务，覆盖普通、短暂失落、第三方转述、持续低落及持续担忧。
- backend/tools/check_conditional_voice.py：在专用空演示库中，用虚构 WAV 经真实语音服务检查自动检测、任务下发、记录与报告分支，不打开真实音频设备。
- test_concern_detector.py / test_guided_screening.py：验证无触发无量表、自动切换、过期推理、服务失败、拒绝/暂停、逐项依据、缺项及用户隔离。

本机回执在 开发结果/20261111_按需心理信息采集。虚构示例与软件回归不替代真人体验、专业评估或独立验收。
