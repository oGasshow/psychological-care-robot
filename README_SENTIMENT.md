# 逐句用户表达情绪

2026-11-12：修复用户发言普遍显示“无法判断”、原话旁没有分类标签的问题。原 worker 确实运行，但启动器强制使用有限关键词规则；未命中规则的日常表达和功能问题不能得到合适类别。现在可以使用已开通豆包权限进行语义分类，原始对话旁显示每条用户发言的结果，处理中自动更新。

## 当前口径

- 只分析用户最终文字；助手回复不打用户情绪标签、不进入分母。取消或未完成文字不参与。
- 输出积极／中性／消极；普通事实陈述、功能提问和无明显倾向的表达属于中性，不因出现“心理不健康”等词就推断用户消极。
- 确实损坏、残缺或正负冲突无法分主次时保留“无法判断”；接口失败显示分析失败或重试，不假冒中性。
- 这是文字表达情绪分类，不是心理健康诊断，与是否触发 PHQ-9/GAD-7 采集独立。危险表达仍由原独立规则处理，不被情绪标签覆盖。

## 配置与运行

在本机忽略的 backend/.env 配置（复用现有 DOUBAO_VOICE_API_KEY）：

```dotenv
ROBOT_CARE_ANALYSIS_ENGINE=doubao_realtime
ROBOT_CARE_SENTIMENT_TIMEOUT_SECONDS=45
# 默认模型 worker 租期为90秒，若显式设置须覆盖请求超时及收尾时间。
```

然后使用 Resume-Project.cmd 继续原数据。启动器现在尊重进程环境／本地配置的引擎选择，不再覆盖成 rules；未配置时仍默认 rules。原 rules 和 Ollama 适配保持可用。care_core 独立标准库 CLI 保持原协议；豆包适配属于服务端 app.care.sentiment。

声音最终文字在结束会话后经既有 Outbox 上传，worker 随后逐条处理。长会话可能需要等待，页面显示“待分析／分析中／等待重试”，每三秒刷新分析状态。积极、中性、消极总数和原话旁标签都引用当前输入及配置版本的结果；旧版本结果不混入统计。

引擎变化会自动创建新版本分析任务、使旧结果失效，但不改写原话，不删除旧版本结果。已保存的历史用户发言也会重新排队，不需要重新录一遍。页面可以看到当前标签和下方版本来源，助手回复不计入用户分类数量。

后台通过独立豆包结构化会话分类，不打开本机音频设备，也不把固定合成触发语音记为用户发言；云密钥只在服务端。该链路沿用原任务租期、幂等、输入更正和删除语义。

## 验证

backend/tools/check_sentiment_model.py 使用虚构积极、消极和功能提问，实际调用模型并记录预期与结果。测试覆盖旧规则未知结果重新分析、逐记录引用、助手排除、非法模型输出、请求失败、独立危险提示及配置优先级。开发回执在本机 开发结果/20261112_逐句情绪分类，不上传运行账号、密钥或数据库。

三类示例与工程回归证明调用和展示链路可用，不代表测量过真实人群分类准确率或临床有效性。

## 独立危险表达提示（2026-11-12）

已修复“我有点不想活了都。”因含“有点”而漏检的问题，覆盖有限的第一人称缓和修饰；否认、引号内引用、他人转述及明确假设仍不作为本人明确危险表达。规则并不穷尽所有表达，未检出不等于无风险。

会话摘要、原话旁和报告顶部共用当前有效用户原话的独立检查，不等待情绪模型或任务完成；更正、删除、用户隔离及报告时间范围均影响提示。消极情绪标签和危险提示可以同时存在，提示需要人工关注与核实，不输出临床风险等级。该表达在实时语音控制器中也优先停止量表信息采集。

模型返回不合规时按既有 worker 上限重试（默认最多三次）；失败后仍保留独立安全信号，不补成中性。配置指纹记录这一执行策略，便于历史结果重排与来源审计。
