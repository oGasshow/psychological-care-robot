# 心理疏导机器人系统

面向心理疏导与辅助陪伴机器人的软件项目。本仓库用于项目开发、版本管理和本地复现；当前增量开发覆盖对话文字记录与上传、异步情绪分析、网页查询和打印报告。

本地启动器带有虚构基线数据；随后接入的语音对话按实际转写另存。2026-11-11 已接通真实豆包全双工语音与报告文字生成；使用合成语音进行开发联调。真人麦克风体验、树莓派硬件、公司部署与机器人动作仍需现场验证。

报告改版见 [近期陪伴回顾与模型配置说明](README_REPORTS.md)。报告复用开源 Card 模板，展示近期概况、按日表达、周期对比、话题原话和交流建议。新增 [语音接入与树莓派接口](README_VOICE.md)：Windows 网页可直接语音交流，最终文字进入既有记录、分析和报告链路；云端凭证仅保存在服务端。

## 当前功能

2026-11-11 新范围：[按需触发的对话辅助采集](README_GUIDED_SCREENING.md)：用途由购买须知说明，会话无需勾选或取得口头同意。后台根据对话上下文判断是否需要进一步了解，再通过豆包自然采集相关 PHQ-9 / GAD-7 信息；普通用户的报告没有空量表模块。当前是可运行的上下文检测原型，结果待核实，不等同正式施测或 SEGA 复现。

- **记录与上传**：保存对话文字，支持会话结束后上传、失败补传和幂等去重。
- **语音陪伴**：浏览器收音、真实豆包动态回复、PCM 播放、字幕、暂停收音与打断；保留独立 Windows/Pi 终端适配器。
- **异步分析**：独立 worker 逐条处理用户文字，可配置豆包语义三分类；原话旁显示积极／中性／消极标签，旧规则和 Ollama 适配保留。详见 [逐句情绪分类](README_SENTIMENT.md)。
- **历史与更正**：查看历史记录，更正转录时保留原文及输入版本。
- **趋势回顾**：按来源、引擎、版本及测试属性展示对话分类；旧量表只读页保留，按需对话辅助采集结果独立标记。
- **报告与打印**：生成面向用户的近期陪伴回顾，支持规则/可配置模型文字、原话依据、预览和 PDF 打印。
- **安装与复核**：按锁文件安装项目独立环境，提供本地演示、回归和进程停启检查入口。

本轮已将 2.1 的真实语音接入 2.4／2.3／2.6；机器人动作策略仍需整机联调。量表范围已按新要求调整为仅检测有进一步了解需求时的对话辅助采集，历史停做量表的说明按原时间理解。

## 本地运行

Windows 安装依赖后，可直接双击根目录中的脚本：

- [Start-Project.cmd](Start-Project.cmd)：恢复固定汇报对话，启动接口、分析 worker 和网页。
- [Start-Presentation.cmd](Start-Presentation.cmd)：同上，每次恢复 3 段、共 12 条虚构对话：日常积极、孤独担忧、明确危险表达，并保留最初的 3 条虚构量表结果。新报告不再堆叠这些量表，默认近 7 天含今天；只有记录足够的完整周期才展示对比。
- [Resume-Project.cmd](Resume-Project.cmd)：继续最近一次运行的数据，不清空。
- [Start-API.cmd](Start-API.cmd)：仅启动接口和分析 worker，打开接口文档。
- [Stop-Project.cmd](Stop-Project.cmd)：停止上述脚本启动的服务。

启动窗口显示实际访问地址和本机虚构演示账号；构建过程中请等待完成。脚本使用项目自己的 `.venv`。每次汇报启动使用独立的 `runtime/presentation_时间戳` 目录，恢复固定对话，不导入旧更正稿或现场操作残留；旧数据库完整保留。继续同一次汇报的数据请使用 Resume-Project.cmd。对话记录页的“新增演示对话”支持现场输入用户文字及可选的手动助手文字，保存后进入真实记录、后台规则分析和报告链路，该新增入口的内容标记为模拟数据，助手文字由操作者填入；用户文字按当前分析引擎处理，配置豆包分析时会调用真实分类服务。新增入口只在专用本地开发演示环境开放，生产环境禁用。未安装依赖时，先按以下步骤运行 Setup-Project.ps1。

会话摘要、原话旁和报告顶部单列明确危险表达提示，并列出当前有效用户对话中的触发表达、来源和修订版本；已修复“我有点不想活了都。”的漏检。否认、引用、他人转述、明确假设及普通消极情绪不按明确危险表达计入，量表分数不触发该提示。提示不依赖模型或分析任务完成，需要人工核实，不作临床风险等级判断。后台量表页另列实际对话采集进度与已确认条目，模拟量表折叠展示；未采齐不生成总分。

已在 Windows 验证的工具组合为 Node.js 22.14.0、npm 10.9.2、uv 0.13.6、Python 3.13.18 和已安装的 Microsoft Edge。

在 PowerShell 中克隆并安装：

```powershell
git clone https://github.com/oGasshow/psychological-care-robot.git
Set-Location psychological-care-robot
./Setup-Project.ps1 -UvExecutable '<uv可执行文件路径>' -PythonExecutable '<Python可执行文件路径或3.13.18>'
```

安装脚本创建本项目 `.venv`，按 `backend/uv.lock` 安装后端开发依赖，通过 `npm ci` 安装前端，并检查工具版本、依赖一致性和锁文件哈希。工具在 PATH 中时也可使用脚本默认参数；完整参数见安装文档。

准备并启动专用虚构演示：

```powershell
./.venv/Scripts/python.exe backend/tools/demo_care.py prepare --runtime runtime/my_demo_001
./.venv/Scripts/python.exe backend/tools/demo_care.py start --runtime runtime/my_demo_001
```

打开 `start` 输出的 `/robot-care` 地址。虚构账号和随机密码保存在本机 `runtime/my_demo_001/access.json`，不提交到 GitHub。`prepare` 需要新的运行目录；首次 `start` 会构建前端并启动 API、分析 worker 和 Next.js。

停止本次演示：

```powershell
./.venv/Scripts/python.exe backend/tools/demo_care.py stop --runtime runtime/my_demo_001
```

重复启动保留同一演示库的数据。安装环境和运行数据由本机生成，不随仓库分发。
